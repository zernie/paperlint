# Could the skills and hooks ship as a Claude Code plugin?

Checked 2026-11-21 against the Claude Code docs (code.claude.com/docs/en/). Asked because the
consumer's `trigger-ledger --check` goes red on every release that rewrites a skill description
(#613, #566), and a plugin would keep package skills out of the consumer's `.claude/skills/`.

## Verdict

**Not as the only channel, and not as the fix for #613.**

1. **A cloud session loads no plugin a repository or a user turns on.** What reaches a cloud
   session is what the clone carries: `.claude/skills/` and the hooks in `.claude/settings.json`.
   A plugin-only install gives a web session zero skills and zero hooks, silently.
2. **The 60-second dependency install is real** (it was quoted in `plugin/CLAUDE.md` without a
   source until now). It needs an npm lockfile inside the published tarball
   (`npm-shrinkwrap.json`), runs no lifecycle scripts, cannot be turned off, and a failure leaves
   the plugin loaded without `node_modules`.
3. **A copied plugin holds only what is under its root**, so a script that imports the package's
   own modules from above the plugin directory finds nothing. Bundling each hook and skill script
   into one self-contained file removes both 2 and 3 for those scripts. It does not remove 1, and a
   skill that runs the `paperlint` CLI still needs the npm package in the project.
4. **#613 is about ownership, not delivery.** A plugin would hide package skills from the
   consumer's ledger only by accident, and only on the surfaces where plugins load.
