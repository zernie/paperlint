# Failure catalog — what went wrong in real grids, the rule, and what holds it

Each entry: the failure as it happened (generic), the rule it produced, and what holds the rule.
"Prose only" means nothing refuses the mistake; the rule holds while someone reads it. A new failure
gets a new entry here, and the entry names its mechanism or says that it has none.

`grid-guard` is `scripts/grid-guard.mjs` in this skill.

## What the guard does not see

- **Who** wrote a field. `approval.by` is compared with `author`; an agent that writes the author's
  name passes. Keep the approval in its own commit, quoting the author's message.
- **The population** behind the registry. The guard checks the registry's own consistency, not that
  the frame was the whole population.
- **Key shapes it does not know.** `scan-keys` matches forms (key blocks, token prefixes,
  `NAME=value` with a secret-looking name). A credential in an unknown shape passes; the environment
  probe, which works on names, is the first line.
- **Whether a run was read.** Nothing mechanical tells a read transcript from an unread one.
