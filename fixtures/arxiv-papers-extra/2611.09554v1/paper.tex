\begin{abstract}
Long-context language models often neglect information in the middle of the input, a phenomenon known as ``lost-in-the-middle''. Part of this gap may stem from the long-range decay of rotary position embedding (RoPE), which weakens the positional signal between distant tokens. Existing input compression deletes low-importance tokens, and attention reweighting acts only after RoPE has weakened this signal. RoPE-level methods modify positions directly but apply the same remapping to every query. To address these limitations, we propose \textbf{QGPM} (Query-Guided Positional Modulation), a training-free method that reshapes RoPE positions using query relevance from the model's own attention heads. QGPM builds a broad relevance map for lower layers and a sharp one for upper layers. Low-relevance tokens advance by less than one position on fast-rotating planes, pulling relevant evidence toward the query. Slow-rotating planes keep the original layout, with every token in place. Experiments on NoLiMa and RULER with multiple context lengths show that QGPM improves over base models and strong baselines, with the largest gains on retrieval tasks, and generalizes across multiple backbones. Our code is available at \url{https://github.com/iZHpy/QGPM}.
\end{abstract}

\section{Introduction}

Long-context language models now support context windows of hundreds of thousands of tokens~\citep{achiam2023gpt,grattafiori2024llama,yang2024qwen2}. Whether these models actually use the information in such windows, however, remains an open question. Models often attend to the beginning and end of the input while neglecting the middle, a phenomenon known as ``lost-in-the-middle''~\citep{liu2024lost}. Benchmarks designed to probe context utilization~\citep{modarressi2025nolima,hsieh2024ruler} show that accuracy drops sharply as context grows, especially when the relevant evidence shares little surface overlap with the query. This paper therefore aims to improve how models use the information already in the context window, rather than to extend the window further.

Part of this utilization gap may stem from rotary position embedding (RoPE)~\citep{su2024roformer}, the position encoding adopted by most modern LLMs. RoPE represents position as rotations in many two-dimensional planes, each with a distinct frequency. Over a long distance, the fast-rotating planes complete many full turns and no longer carry a consistent distance signal. Evidence far from the query is thus matched through fewer planes than nearby text. This long-range decay depends on the positional distance between tokens. Assigning relevant evidence a position closer to the query can therefore mitigate the decay without changing the input text.

Existing methods that target lost-in-the-middle fall short of intervening on RoPE in a query-aware manner. Input compression methods~\citep{jiang2024longllmlingua,pan2024llmlingua2,li2023compressing} delete low-importance tokens and thus discard graded relevance information. Attention reweighting methods~\citep{zhang2024tell,zhang2024model,guardieiro2025instruction} strengthen attention to selected tokens, but only after RoPE has weakened the positional signal between distant tokens. RoPE-level methods~\citep{zhang2024found,jin2024llm,an2025why} modify position encoding directly, yet apply the same remapping regardless of the query. A separate line of work shows that a few attention heads already attend to query-relevant spans in long inputs~\citep{wu2025retrieval,zhang2025query}. Such attention signals have been used to select KV cache entries~\citep{li2024snapkv}, filter input tokens~\citep{shi2026discovering}, or re-rank documents~\citep{zhang2025query}, but always by deleting or reordering content. In short, no existing method uses the model's own query relevance to reshape RoPE positions while keeping every token in place.

We propose \textbf{QGPM} (Query-Guided Positional Modulation), a training-free method that fills this gap. QGPM reads the attention from the query to each context sentence in a few such heads. The resulting relevance ranking is shaped into a broad map and a sharp map. Using the two maps, QGPM lets low-relevance tokens advance by less than one position on the fast-rotating planes, so relevant sentences move closer to the query. In contrast, the slow-rotating planes keep the original layout of the document. The broad map is applied to the lower layers and the sharp map to the upper layers. QGPM deletes or reorders no token and updates no model weight.

Our main contributions are as follows:

\begin{itemize}
    \item We propose QGPM, which converts query relevance read from the model's own attention heads into token-level and frequency-specific RoPE positions. The same context thus receives different positions under different queries, which makes the evidence needed by each query easier for the model to retrieve.
    \item We design a modulation scheme that is aware of both frequency and depth. Low-relevance text is compressed only on fast-rotating planes, and separate relevance maps guide the lower and upper layers.
    \item Comprehensive experiments on multiple LLM backbones and long-context benchmarks show that QGPM achieves superior overall performance over strong baselines across a range of context lengths.
\end{itemize}



\section{Related Work}
\label{sec:related-work}

\subsection{Mitigating Lost-in-the-Middle}

Inference-time methods for lost-in-the-middle~\citep{liu2024lost} mostly edit the input or the attention weights without touching position encoding. Input compression methods such as Selective Context~\citep{li2023compressing}, LongLLMLingua~\citep{jiang2024longllmlingua}, and LLMLingua-2~\citep{pan2024llmlingua2} delete tokens judged unimportant. TAG~\citep{pal2025tagging} instead inserts tags that mark salient content. Attention reweighting methods such as PASTA~\citep{zhang2024tell}, AutoPASTA~\citep{zhang2024model}, and InstABoost~\citep{guardieiro2025instruction} amplify attention to selected tokens, and \citet{hsieh2024found} calibrate the positional bias in attention. Deletion loses information, and tagging leaves the long-range decay untouched. Attention-side methods can only rescale a positional signal that RoPE has already weakened.

\subsection{RoPE and Position Modification}

Most RoPE modifications extend the context window by rescaling position indices, as in Position Interpolation~\citep{chen2023extending}, YaRN~\citep{peng2024yarn}, and LongRoPE~\citep{ding2024longrope}. Fewer methods improve utilization within the window. Ms-PoE~\citep{zhang2024found} rescales positions with head-specific ratios, and Self-Extend~\citep{jin2024llm} maps distant positions back into the trained range by grouping. STRING~\citep{an2025why} reuses well-trained positions for long distances, and Position Engineering~\citep{he2024position} inserts placeholder positions tuned for each task. All of these remappings are fixed before the query is seen, whereas QGPM derives the remapping from the query.

\subsection{Attention as a Relevance Signal}

Attention itself provides a reliable relevance signal in long inputs. A sparse set of retrieval heads copies information from long contexts~\citep{wu2025retrieval}, and QRHead~\citep{zhang2025query} uses query-focused heads to re-rank documents. Attention sorting~\citep{peysakhovich2023attention} reorders documents by attention, while SnapKV~\citep{li2024snapkv} and GemFilter~\citep{shi2026discovering} use attention to select KV cache entries and input tokens, respectively. All of these methods use the signal to select or reorder content. QGPM instead uses a similar query-to-context signal to modulate RoPE positions, so every token stays in the input.


\section{Preliminaries}
\label{sec:preliminary}

\subsection{Rotary Position Embedding}

RoPE~\citep{su2024roformer} splits each query and key vector of dimension $d$ into $d/2$ two-dimensional planes. Plane $m$ rotates with angular frequency
\begin{equation}
\omega_m = \theta^{-2m/d}, \quad m = 0, 1, \ldots, d/2 - 1,
\label{eq:rope-freq}
\end{equation}
where $\theta$ is a base constant, typically between $10^4$ and $10^8$. Plane $m = 0$ rotates fastest. A token at position $p$ is rotated by $R(p) = \mathrm{diag}\big(R_2(\omega_0 p), \ldots, R_2(\omega_{d/2-1} p)\big)$, where $R_2(\phi)$ is a planar rotation by angle $\phi$. For a query vector $q_i$ at position $p_i$ and a key vector $k_j$ at position $p_j$, the identity $R(p_i)^\top R(p_j) = R(p_j - p_i)$ gives
\begin{equation}
\begin{aligned}
\mathrm{logit}(i, j) &= q_i^\top R(-\Delta p)\, k_j \\
&= \sum_{m=0}^{d/2-1} \big[\, a_m \cos(\omega_m \Delta p) \\
&\qquad\quad + b_m \sin(\omega_m \Delta p) \,\big],
\end{aligned}
\label{eq:rope-expansion}
\end{equation}
where $\Delta p = p_i - p_j$, $a_m = q_{i,2m} k_{j,2m} + q_{i,2m+1} k_{j,2m+1}$, and $b_m = q_{i,2m} k_{j,2m+1} - q_{i,2m+1} k_{j,2m}$. The logit thus depends on position only through $\Delta p$, and each plane adds one oscillating term.

\subsection{Frequency Planes and Long-Range Decay}

Plane $m$ completes one full turn every $\lambda_m = 2\pi/\omega_m$ positions, and $\lambda_m$ grows exponentially with $m$. At a distance $\Delta p$, every plane with $\lambda_m < \Delta p$ has turned at least once. The terms of these planes in Equation~\ref{eq:rope-expansion} no longer change consistently with distance and tend to average out across nearby keys. Only planes with $\lambda_m > \Delta p$ keep a coherent distance signal, namely the planes above the boundary index
\begin{equation}
m(\Delta p) = \frac{d \ln(\Delta p / 2\pi)}{2 \ln \theta}.
\label{eq:wrap-index}
\end{equation}
Since $m(\Delta p)$ grows with $\Delta p$, distant evidence is matched through fewer planes than nearby text. For example, with $\theta = 10^7$ and $d = 128$, about 53 of 64 planes stay coherent at 100 tokens, but only about 30 at 32K tokens. We refer to this effect as the long-range decay of RoPE.

The same view suggests how to counter the decay. Shrinking the distance between the query and relevant evidence from $\Delta p$ to $\Delta p'$ restores coherence on every plane with $\Delta p' < \lambda_m < \Delta p$. Slow planes with wavelengths beyond the context length stay coherent at any distance and keep the coarse layout of the document. These planes need no change. Fast planes also encode local word order, so changes on fast planes should be limited to text that is irrelevant to the query.



\section{Method: QGPM}
\label{sec:method}

QGPM runs the backbone twice on each input (Figure~\ref{fig:pipeline}). A plain prefill first measures how strongly the query attends to each context sentence (Section~\ref{sec:method-scoring}). The resulting ranking is shaped into a broad and a sharp relevance map (Section~\ref{sec:method-maps}). In the answering pass, each map sets plane-specific strides (Section~\ref{sec:method-stride}), and the accumulated strides replace the original positions in RoPE (Section~\ref{sec:method-remapping}).

\subsection{Relevance from Attention Heads}
\label{sec:method-scoring}

QGPM reads relevance from a small set $\mathcal{H}$ of attention heads. The heads are selected once per backbone by how well each head ranks annotated evidence on a held-out set (Appendix~\ref{app:heads}). Let $\mathcal{Q}$ denote the query rows, namely the question tokens and the last few prompt tokens (Appendix~\ref{app:implementation}). For head $h$ and context token $j$, the relevance signal is the largest RoPE logit from any query row:
\begin{equation}
\ell_h(j) = \max_{r \in \mathcal{Q}} \frac{\big(R(p_r)\, q_{h,r}\big)^\top \big(R(p_j)\, k_{h,j}\big)}{\sqrt{d}}.
\label{eq:head-signal}
\end{equation}
QGPM splits the context into sentences $S_1, \ldots, S_n$ and scores each sentence by the strongest token in the sentence, $\ell_h(S_i) = \max_{j \in S_i} \ell_h(j)$. Each head is standardized over sentences, and the heads are averaged:
\begin{equation}
z_i = \frac{1}{|\mathcal{H}|} \sum_{h \in \mathcal{H}} \frac{\ell_h(S_i) - \mu_h}{\sigma_h},
\label{eq:fusion}
\end{equation}
where $\mu_h$ and $\sigma_h$ are the mean and standard deviation of $\ell_h(S_i)$ over sentences.

\subsection{Broad and Sharp Relevance Maps}
\label{sec:method-maps}

The scale of $z_i$ varies across inputs, so QGPM keeps only the order of the sentences. Let $\rho(i)$ be the rank of $S_i$ by $z_i$, with $\rho(i) = 0$ for the most relevant sentence. The score of $S_i$ is
\begin{equation}
\begin{aligned}
f_i &= \sigma\big((K - 0.5 - \rho(i)) / T\big), \\
s_i &= s_{\mathrm{low}} + (1 - s_{\mathrm{low}})\, \tilde f_i,
\end{aligned}
\label{eq:rank-scoring}
\end{equation}
where $\sigma(\cdot)$ is the sigmoid function and $\tilde f_i$ rescales $f_i$ to $[0, 1]$ over sentences. The top sentence thus receives a score of 1, and the bottom sentence receives $s_{\mathrm{low}}$. The center $K$ sets how many sentences stay near 1, and the temperature $T$ sets how quickly the scores fall off. Setting $T = 0$ gives a hard top-$K$ cut.

QGPM shapes the same ranking twice. The broad map uses a larger $K$ and a softer $T$, so several candidate sentences stay relevant. The sharp map uses a smaller $K$ and a harder $T$, so only the top sentences stay relevant. Each token inherits the score of the enclosing sentence. Tokens outside the context, such as the instruction and the question, always receive a score of 1.

We call a sentence relevant if the sentence score is at least $(1 + s_{\mathrm{low}})/2$. In each map, all context tokens before the first relevant sentence also receive a score of 1 and form a protected prefix. Under causal attention, the representation of the evidence is built from the text before the evidence. Keeping this prefix intact preserves the encoding of the evidence. Compression is then limited to the text between the evidence and the query, which is the span that sets the distance between the two.

\begin{algorithm}[t]
\caption{QGPM inference}
\label{alg:qgpm}
\begin{algorithmic}[1]
\Require context sentences $S_1, \ldots, S_n$, heads $\mathcal{H}$, query rows $\mathcal{Q}$
\Require hyperparameters $(K_b, T_b)$, $(K_s, T_s)$, $s_{\mathrm{low}}$, $L_a$, $\tau_m$, $\epsilon$
\Statex \textit{Pass 1: relevance scoring}
\State Run a plain prefill up to the deepest layer in $\mathcal{H}$
\State Compute $\ell_h(j)$ and $z_i$ by Eqs.~\ref{eq:head-signal} and~\ref{eq:fusion}
\State Rank the sentences by $z_i$ to obtain $\rho(i)$
\For{each map $g \in \{\text{broad}, \text{sharp}\}$}
    \State Score sentences by Eq.~\ref{eq:rank-scoring} with $(K_g, T_g)$
    \State Set scores of non-context tokens and the protected prefix to 1
    \State Compute strides by Eq.~\ref{eq:stride} with $m^* = m(L_a)$
    \State Accumulate positions $p'_{m,j}$ by Eq.~\ref{eq:cumsum}
\EndFor
\Statex \textit{Pass 2: answering}
\State Prefill with the broad map below layer $\ell_s$ and the sharp map from $\ell_s$ on
\State Decode in unit steps from $p'_{m,N-1}$ of each map
\end{algorithmic}
\end{algorithm}

\subsection{Frequency-Aware Strides}
\label{sec:method-stride}

Following Section~\ref{sec:preliminary}, QGPM changes only the fast planes. Given an anchor length $L_a$ proportional to the context length, the boundary plane is $m^* = m(L_a)$ from Equation~\ref{eq:wrap-index}. Planes with $m < m^*$ complete at least one turn within $L_a$ tokens and count as fast. The remaining planes count as slow. A sigmoid gate of width $\tau_m$ separates the two groups. For a map with token scores $s(j)$, the stride $\delta_m(j)$ of token $j$ on plane $m$ is
\begin{equation}
\begin{aligned}
g_m &= \sigma\big((m - m^*) / \tau_m\big), \\
\delta_m(j) &= \max\big(s(j) + (1 - s(j))\, g_m,\ \epsilon\big),
\end{aligned}
\label{eq:stride}
\end{equation}
where $\epsilon$ is a stride floor. On slow planes $g_m \approx 1$, so every token keeps unit stride. On fast planes $g_m \approx 0$, so the stride falls to about $\max(s(j), \epsilon)$. Relevant sentences, whose scores are close to 1, thus keep near-unit stride on every plane, and only low-relevance tokens on fast planes are compressed.

The floor $\epsilon$ keeps fast-plane increments close to the range seen in pretraining. With a small floor, about $1/\epsilon$ consecutive low-relevance tokens share one position on each fast plane, so the local order of these tokens is largely lost. We hypothesize that this blur de-emphasizes distractor text without deleting the text, while the slow planes still place every token correctly within the document.

\subsection{Remapped Positions and Layer Schedule}
\label{sec:method-remapping}

Remapped positions accumulate the strides:
\begin{equation}
p'_{m,j} = \sum_{k=1}^{j} \delta_m(k).
\label{eq:cumsum}
\end{equation}
Every stride is at least $\epsilon > 0$, so positions stay strictly increasing. Token $j$ is rotated by $\omega_m p'_{m,j}$ on plane $m$, and the logit follows Equation~\ref{eq:rope-expansion} with $\Delta p$ replaced by the plane-specific offset $\Delta p'_{m,ij} = p'_{m,i} - p'_{m,j}$. Because positions accumulate, unit stride does not mean an unchanged position. On fast planes, every token after a compressed span moves toward the span, which brings relevant sentences closer to the query. Distances within the query are preserved exactly, and distances within relevant sentences are preserved approximately.

QGPM computes one set of positions for each map. Layers below $\ell_s = \lfloor n_{\mathrm{layer}}/2 \rfloor$ use the broad map, and the remaining layers use the sharp map. Each layer stores the KV cache in the coordinates of the corresponding map. We hypothesize a division of labor across depth. Lower layers build token representations from local context, so text blurred there cannot be recovered later. The broad map therefore keeps several candidate sentences intact in these layers. The selected heads lie mostly in the middle and upper layers, where the sharp map leaves fewer competing sentences near the query.

During decoding, the $k$-th generated token takes position $p'_{m,N-1} + k$ on each plane of each map, where $N$ is the prompt length. Decoding thus continues in unit steps from the last prompt position. Compared with standard inference, QGPM adds one plain prefill that stops at the deepest selected layer. The per-token cost of decoding stays equal to that of standard RoPE (Appendix~\ref{app:cost}). Algorithm~\ref{alg:qgpm} summarizes the full procedure, and Appendix~\ref{app:hyperparams} describes all hyperparameters.

We organize the experiments around three research questions.
\begin{itemize}
    \setlength{\itemsep}{0pt}
    \setlength{\parskip}{0pt}
    \item \textbf{RQ1:} Does QGPM outperform existing inference-time methods across backbones, tasks, and context lengths?
    \item \textbf{RQ2:} Is modulating RoPE positions more effective than selecting or reordering content by relevance?
    \item \textbf{RQ3:} How close does the relevance read from attention heads come to gold evidence?

\subsection{Experimental Setup}
\label{sec:exp-setup}

\paragraph{Models.}
We evaluate four instruction-tuned backbones from three model families: Qwen2.5-7B-Instruct-1M~\citep{yang2025qwen251m}, Qwen3-4B-Instruct-2507~\citep{yang2025qwen3}, Ministral-8B-Instruct-2410~\citep{mistral2024ministraux}, and Granite-3.3-8B-Instruct~\citep{ibm2025granite33}. The RoPE bases of the four backbones range from $5 \times 10^6$ to $10^8$. Except for Ministral-8B at 64K,\footnote{For Ministral-8B, 64K exceeds the 32,768-token limit in its HuggingFace configuration (\texttt{max\_\allowbreak position\_\allowbreak embeddings} and \texttt{sliding\_\allowbreak window}). Results at this length therefore reflect behavior beyond the configured window and are reported for completeness.} all inputs fit within the native context window of each backbone, and we apply no length extrapolation.

\paragraph{Benchmarks and metrics.}
NoLiMa~\citep{modarressi2025nolima} tests retrieval when the evidence shares little lexical overlap with the question. We evaluate NoLiMa at 4K, 8K, 16K, and 32K tokens. From RULER~\citep{hsieh2024ruler}, we use two question answering tasks, single-hop QA-1 and multi-hop QA-2, and two retrieval tasks, NIAH-MK and NIAH-MV. We evaluate the RULER tasks at 4K, 8K, 16K, 32K, and 64K tokens. NIAH-MK hides one target key among many similar keys, and NIAH-MV asks for all values of one key. We report accuracy (\%) on every task. Correctness is judged by whether the response contains the required gold answers (Appendix~\ref{app:implementation}).

\paragraph{Baselines.}
We compare QGPM with the unmodified backbone, denoted Vanilla, and with four inference-time methods. LLMLingua-2~\citep{pan2024llmlingua2} represents input compression. Ms-PoE~\citep{zhang2024found}, Self-Extend~\citep{jin2024llm}, and STRING~\citep{an2025why} modify RoPE positions without using the query. All baselines use the default settings recommended in the original papers (Appendix~\ref{app:implementation}).

\paragraph{Implementation details.}
All methods use greedy decoding and run with PyTorch and HuggingFace Transformers on NVIDIA A100 GPUs. Appendix~\ref{app:heads} describes head selection, and Appendix~\ref{app:hyperparams} describes the hyperparameters for each backbone and dataset.

Self-Extend drops to 58.0 on NIAH-MK at 64K for Qwen2.5, where Vanilla keeps 91.4. A fixed remapping treats evidence and distractors alike, which may explain these drops. STRING is the strongest baseline, yet the five-task average of STRING still falls below Vanilla on Qwen2.5.

On NIAH-MV, QGPM improves on Vanilla at every length on Qwen2.5, by 7.8 to 14.2 points. On QA, QGPM tracks Vanilla closely, and small gains appear mainly at 64K, where QGPM exceeds Vanilla in seven of eight settings.

We compare QGPM with two variants that edit the input according to relevance. Both variants split the context into chunks and score each chunk against the question with Qwen3-Reranker-4B~\citep{zhang2025qwen3embedding}. Top-K keeps the five highest-scoring chunks and drops the rest. Reorder keeps all chunks and sorts the chunks by relevance, so that the most relevant chunk lies closest to the query. QGPM instead keeps every token in place and needs no external ranker. The tokenizer of the reranker is not fully compatible with those of Ministral-8B and Granite-3.3-8B, so we run this comparison on Qwen2.5-7B only.

Table~\ref{tab:ablation} reports the averages, and Figure~\ref{fig:edit-length} shows each context length. On NoLiMa, both variants outperform Vanilla and STRING, with 41.1 points for Top-K and 39.9 points for Reorder. Query relevance thus helps even without positional modulation. QGPM reaches 46.1 points and stays above both variants at every length, by 0.4 to 10.2 points. On NIAH-MV, QGPM also leads with 93.4 points, against 92.2 for Reorder and 91.1 for Top-K. The margin over Top-K reaches 5.2 points at 64K, likely because the five kept chunks do not always cover every value of the key. Top-K loses any evidence that the ranker misses, and Reorder breaks the original order of the document. QGPM avoids both risks because every token stays in the input. On QA-1, the three methods perform on par, and Top-K is 0.2 points above QGPM. Unlike NoLiMa, QA-1 does not minimize the lexical overlap between question and evidence, so the ranker likely keeps the evidence and deletion costs little.


\subsection{Quality of Head Relevance (RQ3)}
\label{sec:exp-oracle}

Oracle replaces the relevance read from attention heads with evidence positions marked by hand from the benchmark labels. All other steps stay unchanged, including the two maps, the protected prefix, and the frequency gate. Any gap between QGPM and Oracle therefore comes from the relevance signal alone. Marking the evidence by hand is costly, so we run Oracle on Qwen2.5-7B only.

On all three tasks of Qwen2.5, QGPM comes within 1.2 points of Oracle (Table~\ref{tab:ablation}). The relevance read from attention heads is thus close to annotated evidence. QGPM even exceeds Oracle at some lengths, such as 8K on NoLiMa and 64K on NIAH-MV (Figure~\ref{fig:edit-length}). Oracle is therefore a reference rather than a strict upper bound.

On NoLiMa and QA-1, the remaining gap concentrates at the longest length. On NoLiMa, Oracle improves on Vanilla by 17.6 to 21.2 points at every length. Moving correctly identified evidence closer to the query thus helps even at 32K. QGPM trails Oracle by at most 2.0 points up to 16K, but the gap grows to 5.7 points at 32K. At this length, the relevance signal rather than the positional modulation limits QGPM. The smaller NoLiMa margin at 32K in Section~\ref{sec:exp-main} likely has the same cause. On QA-1, Oracle gains only 2.0 points over Vanilla on average, so position is not the main bottleneck for this task. The exception is again the longest length, where Oracle gains 8.0 points at 64K and QGPM gains 3.2 points.



\section{Conclusion}
\label{sec:conclusion}

We presented QGPM, a training-free method that reshapes RoPE positions using query relevance read from the model's own attention heads. QGPM compresses low-relevance text only on fast-rotating planes and guides the lower and upper layers with a broad and a sharp relevance map. Every token stays in the input, and no model weight changes. Across four backbones, QGPM achieves the best average accuracy, with the largest gains on retrieval tasks. On question answering, where position matters less, QGPM matches the backbone. Modulating positions also outperforms input editing on retrieval, and the head relevance comes close to annotated evidence. The remaining gap appears at the longest contexts, so better relevance estimation for very long inputs is a promising next step.



\section*{Limitations}

\paragraph{Access to model internals.}
QGPM reads the query and key vectors of selected heads and replaces the RoPE tables of the backbone. The method therefore applies to open-weight models but not to models served only through an API. Most open long-context models use RoPE, so this requirement still covers a broad range of backbones.
 
\paragraph{Extra prefill.}
QGPM adds one plain prefill that stops at the deepest selected layer, which increases the time to the first token. The decoding cost and the size of the KV cache stay unchanged. The context keys in this first pass do not depend on the question. Several questions over the same document could therefore share a cached prefix. A shallower head set would also shorten the first pass.


\section*{Ethics Statement}

This work proposes a training-free inference method that changes how a long-context language model encodes positions. QGPM introduces no new model, training data, or alignment procedure, so the safety and factuality of each backbone remain those of the released model. All experiments use public benchmarks, NoLiMa and RULER, which consist of synthetic or existing question answering instances without personal information. The backbones and the reranker used by the input editing baselines are publicly released models. QGPM requires no fine-tuning, so the computational cost of this work is modest. We are not aware of risks specific to QGPM beyond those of the underlying models.

\section{Head Selection}
\label{app:heads}

QGPM reads relevance from a fixed set $\mathcal{H}$ of attention heads, selected once for each backbone. Every (layer, head) pair of the backbone is a candidate. The calibration set is a fixed subset of NoLiMa samples whose evidence spans are known. The calibration samples are disjoint from the evaluation samples.

For each calibration sample and candidate head, we compute the sentence signal $\ell_h(S_i)$ of Equation~\ref{eq:head-signal} with the same query rows as at inference. The context sentences are then ranked by this signal. The quality of a head is the mean reciprocal rank of the evidence sentence over the calibration samples, with ties counted at the expected rank. The $|\mathcal{H}|$ heads with the highest quality form the head set. Calibration only selects heads and updates no weight.

Three details keep the signal faithful to the attention of the model. Under grouped-query attention, head $h$ reads the key head of the same group. On Qwen3, the vectors are taken after the query and key normalization of the model. Tokens that contain a newline character are excluded from the signal, because the line break around a NoLiMa needle is a formatting artifact that some shallow heads attend to.

The selected heads lie mostly in the middle and upper layers of each backbone, which motivates the layer schedule in Section~\ref{sec:method-remapping}.

\paragraph{Prompts and query rows.}
Each prompt contains a system prompt, a task instruction, the context, the question, and an answer prefix. Only the context is scored, and every other token receives a score of 1. On NoLiMa, the context is a book excerpt with one inserted needle. On RULER, the context is the haystack, and the question is the text from the last \texttt{Question:} onward. The query rows $\mathcal{Q}$ are the question tokens together with the last few tokens of the prompt. All methods read exactly the same prompts and needle placements.

\paragraph{Sentence segmentation.}
The context is split into sentences after ``.'', ``!'', and ``?'' followed by whitespace, with common abbreviations protected. A token belongs to the sentence that contains the first character of the token, and the whitespace between two sentences belongs to the next sentence. Tokens are aligned to sentences through the character offsets of the backbone tokenizer.

\paragraph{Position tables.}
The remapped positions and the cosine and sine tables are computed in FP32 and then cast to the model precision. QGPM builds the tables once per prefill for each map. A forward pre-hook passes the tables of the assigned map to the attention of each decoder layer, so the KV cache of each layer stays in the coordinates of that map. With every score equal to 1, the patched model reproduces the unmodified backbone, which we verify for each backbone.

\paragraph{Decoding and hardware.}
All methods use greedy decoding with the same limit on new tokens for each dataset. The experiments run with PyTorch and HuggingFace Transformers on NVIDIA A100 GPUs.

\paragraph{Metrics.}
Each response is scored as correct or incorrect, and accuracy is the percentage of correct responses. On NoLiMa, a response is correct if the response contains the gold answer. On RULER QA, a response must contain the gold answer, and a question with several required answers needs every answer. NIAH-MK requires the value of the target key, and NIAH-MV requires every value of the key. Each RULER task has 500 samples at each length.

\paragraph{Baselines.}
All baselines use the default settings recommended in the original papers.

\paragraph{Input editing.}
Top-K and Reorder split the context into sentence-aligned chunks and score each chunk against the question with Qwen3-Reranker-4B. Top-K keeps the five highest-scoring chunks and drops the rest. Reorder keeps all chunks and sorts the chunks by score, so that the most relevant chunk ends right before the question. Both variants run with standard RoPE. The tokenizer of the reranker is not fully compatible with those of Ministral-8B and Granite-3.3-8B, so both variants run on Qwen2.5-7B only.

\paragraph{Oracle.}
Oracle marks the evidence in each context by hand according to the benchmark labels, such as the needle in NoLiMa and the gold documents and inserted values in RULER. Oracle marks the gold spans at the token level, whereas the attention scorer of QGPM ranks whole sentences. The two maps, the protected prefix, the frequency gate, and the stride floor stay the same as in QGPM. Because these settings act on both, Oracle is a reference rather than a strict upper bound. Marking evidence by hand is costly, so we run Oracle on Qwen2.5-7B only.

\section{Hyperparameters}
\label{app:hyperparams}

QGPM sets the following hyperparameters for each backbone and dataset. Two settings are shared by all runs. The split layer is $\ell_s = \lfloor n_{\mathrm{layer}}/2 \rfloor$, and the score of the top sentence is 1. The remaining settings play the following roles.
\begin{itemize}
    \setlength{\itemsep}{0pt}
    \setlength{\parskip}{0pt}
    \item The broad map uses $(K_b, T_b)$ and the sharp map uses $(K_s, T_s)$, with $K_b > K_s$ and $T_b > T_s$. $K_s$ is at least the number of evidence spans that a task requires.
    \item The minimum score $s_{\mathrm{low}}$ and the stride floor $\epsilon$ set the strength of compression. A low-relevance token advances by $\max(s_{\mathrm{low}}, \epsilon)$ on a fast plane.
    \item The anchor length is $L_a = c \cdot L$, where $L$ is the context length and $c$ is set for each dataset. For the same $L_a$, a larger $\theta$ gives a smaller $m^*$, so fewer planes are compressed.
    \item The gate width $\tau_m$ is a small value in units of plane index.
\end{itemize}
On NIAH-MK and NIAH-MV, $K_s$ is chosen on development samples for each task and fixed before the evaluation samples are run.

\section{Computational Cost}
\label{app:cost}

QGPM changes the cost of inference in three places.
\begin{itemize}
    \setlength{\itemsep}{0pt}
    \setlength{\parskip}{0pt}
    \item The first pass is a plain prefill that stops right after the key projection of the deepest layer in $\mathcal{H}$. This pass costs at most one plain prefill and becomes cheaper with a shallower head set.
    \item The answering pass is a full prefill with the remapped tables. The attention kernels stay unchanged, so this pass costs the same as a plain prefill. Building the position tables takes $O(N d/2)$ time and memory for each map.
    \item Decoding keeps the cost per step and the KV cache size of standard inference. Each step adds one vector of $d/2$ angles for each map.
\end{itemize}
